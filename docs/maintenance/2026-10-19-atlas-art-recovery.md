# 이야기 그림 로딩 복구 (2026-10-19)

## 확인한 범위

배포된 1·2·3화의 장면 그림 및 작은 그림 72개는 HTTP 200과 올바른 이미지 MIME으로 응답했다. TLS 검증을 거쳐 내려받은 배포 파일을 WebKit에서 열었을 때 세 회차 첫 장면 모두 표시됐다. 실제 사용자 아이폰에서 발생한 전체 누락 원인은 아직 확정하지 않았다.

기존 렌더러는 이미지 요청이 일시적으로 실패하면 재시도하지 않았다. 이 상태를 요청 실패 주입으로 재현했고, 기존 코드에서는 복구 검사가 실패했다. 또한 390px / DPR 3 휴대폰에서는 srcset 때문에 큰 원본이 선택됐다.

## 최소 변경

- 휴대폰 폭 650px 이하 또는 데이터 절약 모드에서는 기존 작은 그림부터 요청한다. 큰 화면의 반응형 이미지는 유지한다.
- 이미지 오류 시 작은 그림과 원본을 순서대로 최대 두 번 재시도한다. 재시도 URL만 새로 만들어 실패한 응답의 재사용을 피한다.
- 계속 실패하거나 10초간 응답이 없으면 ‘그림 다시 불러오기’를 제공한다. 이야기는 계속 읽을 수 있다.
- 세 회차의 공통 렌더러·스타일·부트스트랩 버전을 갱신한다.

본문, 그림 파일, 퀴즈, 카드 조건, 홈페이지, 저장 키, Firebase 데이터는 변경하지 않는다.

## 검사

`NODE_PATH=/workspace/.sansa-tools/node_modules node tests/atlas-art-recovery.cjs`

Chromium/WebKit에서 세 회차 각각 첫 요청 실패, 작은 그림 실패, 전체 실패 후 수동 복구를 검사한다. DPR 3 휴대폰의 첫 요청이 작은 그림인지, 자동 재시도가 제한되는지, 진행 상태와 보호 기록이 바뀌지 않는지 확인한다. 별도로 WebKit에서 오류 이벤트 없는 요청 지연 후 수동 복구를 검사한다.

기존 기능 회귀 검사는 `tests/atlas-episodes.cjs`, `tests/tongdosa-mobile.cjs`, `tests/tongdosa-transport.cjs`로 수행한다. 브라우저 검사는 테스트 인증을 사용하며 실제 사용자 Firebase에 쓰지 않는다. 실제 아이폰에서의 표시 확인은 별도로 필요하다.
