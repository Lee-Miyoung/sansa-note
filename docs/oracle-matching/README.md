# 즉문즉설 고민·해결방안 연결 수정과 새 예시 1,000개

기준 최신 main: `2e52347`. 기존 사용자의 고민 기록·Firebase·IndexedDB 사진·GPS·108 수호카드·비밀도감·음악 및 로그인 정책은 수정하지 않았습니다.

## 실제 원인과 수정

1. 구형 분류는 중첩되는 단어의 개수와 분류별 우선순위를 더해 한 분류를 강제로 선택했습니다. ‘친구의 배신’이나 ‘전 연인의 연락’을 외도·신뢰 문제로 선택하거나, 퇴사를 부정하는 문장도 퇴사로 분류했습니다.
2. 같은 분류에 도착해도 서로 다른 세부 고민의 해결방안을 무작위로 골랐습니다. 분야가 같다는 이유만으로 개별 상황에 맞는 답변이 되는 것은 아니었습니다.
3. 다른 예시를 불러오거나 입력을 고쳐도 이전 답변이 남아, 새 고민에 예전 해결책이 연결된 것처럼 보일 수 있었습니다.

현재는 구체적인 상황에 연결한 답변과 행동을 결정적으로 선택합니다. 일치한 토큰 수를 중복 가산하지 않고 상황 조건의 조합과 초점을 확인합니다. ‘여자친구’와 ‘친구’, ‘약 복용’과 ‘약속’, ‘아이’와 ‘아이디어’, ‘혼자 살기/해보기’와 위기 표현, ‘문자 해석’과 자해 같은 부분 문자열을 구분합니다. 자기 외모 고민·연인의 외모에 대한 끌림·연인에게 외모 평가를 받는 상황도 나눴습니다.

부정된 상황은 긍정 단서로 쓰지 않습니다. 가까운 후보가 여러 개면 임의로 답하지 않고 최대 3개의 작은 확인 버튼을 제공합니다. 맞는 조건이 없으면 구체적인 상황과 원하는 도움을 더 묻습니다. 이를 모든 자유 문장을 완벽하게 이해하는 AI 상담이라고 소개하지 않습니다.

입력이 바뀌거나 다른 예시를 선택하면 이전 답변과 선택지를 바로 지웁니다. 느린 요청의 결과가 나중에 도착해도 마지막 입력을 덮어쓰거나 닫힌 창을 다시 열지 않습니다. 구형 답변은행은 원문 자료로 남겨두되 자동 임의 fallback에 사용하지 않습니다.

## 실제 콘텐츠 추가

| 구분 | 수 |
|---|---:|
| 기존 예시 | 1,974 |
| 신규 예시 | 1,000 |
| 전체 등록 예시 | 2,974 |
| 신규 예시가 속한 구체 상황 | 100 |
| 상황별 답변 모델 | 104 |

새 예시는 100가지 상황별로 10문장씩 직접 작성했습니다. 질문 머리에 같은 접두어만 붙이거나 문맥을 무시한 무작위 조합으로 숫자를 채우지 않았습니다. 공백·문장부호를 제외해도 기존 1,974개 및 신규 예시 사이에 동일 문구가 없습니다. 기존 예시의 내용과 순서는 해시 및 브라우저 원문 배열 비교로 보존했습니다.

- [새 고민 1,000개 전체 이름별 명세](examples.csv)
- [104개 상황별 해결방안과 다음 행동](situations.csv)
- 실제 파일: `data/oracle-examples-1000.json`, `data/oracle-topics.json`.

100개 예시 상황 외에 상대 외모와 끌림·연인/부부 대화·막연한 불안·보증/명의 대여 4개 대응을 별도로 보강했습니다. 위기 대응 예시 20개도 등록·검사하지만, 원치 않는 위기 문장을 장난스러운 무작위 예시로 노출하지 않도록 무작위 후보에서는 제외합니다. 직접 입력된 위기 표현은 해당 도움으로 연결합니다. 위기 여부가 부정되거나 단순한 단어 설명인 경우를 별도 검사합니다.

## 화면·성능·개인정보

기존 마음 처방 모달, 고민 입력창, ‘번뇌 내려놓기’와 ‘아무 고민이나’ 버튼을 그대로 사용합니다. 확인 버튼과 상태 안내만 작게 추가하고 모바일 답변 가독성을 조정했습니다. 새 화면·배너·라이브러리를 추가하지 않았습니다.

분류 JS와 상황 데이터는 즉문즉설을 열 때만 요청합니다. 1,000개 예시 파일은 예시 버튼을 처음 누를 때만 읽고 이후 재사용합니다. 홈페이지 최초 요청에 새 대량 데이터를 미리 싣지 않습니다. [파일 크기](delivery-size.json)는 gzip 추정값이며 실기기 회선의 속도 측정은 아닙니다. 서비스워커 캐시는 v26입니다.

고민 매칭은 브라우저 안에서 수행합니다. 입력한 고민을 외부 AI API·Firebase로 전송하거나 새 기록으로 저장하지 않습니다. 예시 파일은 사용자가 실제로 쓴 고민을 수집한 자료가 아닌 새로 작성한 가상 사례입니다.

## 검증

`node tests/oracle-matching.cjs`:

- 신규 1,000개 중 일반 상황 933개는 해당 답변으로 직접 연결, 여러 상황이 겹친 47개는 예상 상황을 포함한 확인 선택지 제공, 위기 상황 20개는 별도 도움으로 연결.
- 확인 선택지에서 예상 상황을 고르면 해당 해결방안으로 연결됨. 잘못된 자동 확정 답변 0건. 이는 준비된 예시의 검사 수치이며 임의의 모든 자연어 입력에 대한 정확도 수치가 아닙니다.
- 예시에 없는 독립 문장 40개, 부분 문자열·부정·불명확한 문장 19개, 위기 및 화자 구분 10개, 여러 고민이 섞인 문장을 추가 검사.
- 답변 선택에 난수를 사용하지 않음을 검사. 기존 1,974개 및 신규 1,000개 중복 없음.

`tests/oracle-browser.cjs`:

- PC Chromium 1440·갤럭시 크기 Chromium 412·아이폰 크기 WebKit 390·아이패드 크기 WebKit 820 통과. 실제 기기는 사용하지 않았습니다.
- 비로그인 이용, 해결책·화자·부정문·확인 버튼, 같은 고민의 답변 일관성, 입력 수정/예시 선택 후 이전 답변 제거, 추가 1,000건 로딩과 한 번만 등록, 기존 배열 보존, 가로 넘침 없음, 페이지 오류 0건.
- 입력문이 URL/요청 본문에 실리지 않음, 사용자 모의 기록·로컬 진행 기록 보존, 최초 홈페이지에서 새 JS/JSON 미리 요청하지 않음.
- 지연된 분류·예시 요청이 마지막 입력을 덮어쓰지 않음, 데이터 503 후 재시도 성공, 임의 구형 답변으로 대체하지 않음.

현행 사진·로그인/기존 IndexedDB 사진·MY·GPS·느린 네트워크/오프라인 서비스워커·기존 비밀도감·불교용어 사전 회귀 검사도 통과했습니다. [검사 로그와 화면](validation/).

### 구형 테스트의 기존 불일치

`tests/wellness-actions.cjs`는 게스트가 개인 발원문을 저장할 수 있다고 가정해 실패했습니다. 기준 커밋 `2e52347`의 HTML로도 동일한 지점에서 실패함을 확인했습니다. 현재 `scripts/session-policy.js`는 개인 발원 저장을 회원 전용으로 제한합니다. 이번 변경으로 발생한 회귀가 아니며, 이를 통과시키려고 운영 권한 정책을 바꾸지 않았습니다.

추가 검사에서 현행 정책에 맞게 게스트 저장 차단·모의 회원 저장 성공을 확인했습니다. 기존 테스트의 실패를 통과했다고 보고하지 않습니다. 기준 버전과 현재 로그를 validation에 함께 남겼습니다.
