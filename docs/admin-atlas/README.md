# 기존 사이트의 관리자 비밀도감 검토실

접속 경로: `/admin-atlas/`. 기존 홈·메뉴는 변경하지 않고 직접 주소로 접근합니다. 별도 Firebase 프로젝트 배포는 사용하지 않습니다. PR #1 전체를 병합하는 작업도 아닙니다.

## 접근과 데이터

공개 파일에는 로그인 셸, 공통 스타일, 창작 삽화, 사실을 포함하지 않는 공통 대화/질문 및 AES-256-GCM 암호문을 포함합니다. 역사 본문은 인증 후 비공개 원고에서만 선택합니다. 복호화 키와 평문은 Git에 넣지 않습니다. 역사 원고와 원고가 포함된 화면 코드는 공개 파일에 포함하지 않습니다. Google 로그인 준비와 비공개 연결 검사는 분리합니다. 인증 후 실제 비공개 자료를 읽기 전에 전용 `/admin-atlas/sw.js`의 제어를 확인해 루트 워커의 캐시를 차단합니다. Firebase Google 로그인 후 `emailVerified`, 이메일, 토큰의 aud/iss/Google provider를 확인합니다. 관리자 이외에는 DB 원고 요청 자체를 하지 않습니다.

관리자 UID를 인증 세션에서 취득하고 다음 두 경로만 새로 사용합니다.

- `users/{관리자UID}/adminTests/haeinsa-001/draft`: 전용 등록 링크를 통한 관리자 브라우저의 최초 등록 원고·화면 코드 묶음(약 61KB). AES-GCM 인증 및 SHA-256 검증을 통과해야 저장·실행합니다. 최초 등록은 transaction으로 기존 값이 없을 때만 수행하며 이미 등록된 자료를 덮어쓰지 않습니다.
- `users/{관리자UID}/adminTests/haeinsa-001/progress`: 이 검토실의 진행·정답·카드·감상 기록.

기존 `users/{UID}/destinations`는 해인사 인증을 읽기만 합니다. 인증 참조는 별도 progress에만 저장합니다. 실제 GPS 인증이나 기존 기록 수정은 하지 않습니다. 별도 로컬 저장 접두어 `sansaAdminAtlasTest_v1:`를 사용하므로 운영 비밀도감 캐시와도 합치지 않습니다.

사용자가 제공한 현행 규칙의 owner 읽기/쓰기를 그대로 이용합니다. **규칙 배포·변경 없음**. 서버 규칙에서 비인증·타 UID 읽기/쓰기가 차단되는 소유자 경로를 사용하며 관리자 전체 읽기 권한도 변경하지 않습니다. 일반 사용자 본인의 임의 데이터 쓰기를 새로 제한하는 규칙은 추가하지 않습니다. 이 페이지의 UI 검사만으로 서버 보안을 대체하지 않습니다.

현재 저장소가 공개이고 PR #1의 기존 브랜치·커밋에 이미 원고 소스가 있습니다. 이 변경은 배포하는 main에 원고를 추가하지 않지만, 기존 공개 Git 이력의 노출을 철회하거나 그 원고를 완전히 비밀로 만드는 작업은 아닙니다. 공개된 원고의 완전한 비밀성을 보장할 수 없습니다. 사용자 개인 기록은 Git에 포함하지 않습니다.

## 최초 사용

1. 아이폰 Safari에서 이 대화에만 제공한 전용 최초 등록 링크를 누릅니다. 링크의 fragment에 키가 포함되며 서버로 전송되지 않습니다. 즉시 주소/방문 기록에서 제거하고 인증·서비스 워커 재시작 동안 해당 탭의 sessionStorage에만 보관합니다.
2. 관리자 Google 로그인 → 기존 관리자 계정 선택. 파일 선택 없이 암호문을 복호화해 비공개 테스트 경로에 최초 등록합니다. 완료/비관리자 로그인 시 탭의 키를 지웁니다. 비밀번호·인증코드는 보내지 않습니다.
3. 등록 후 비밀도감이 자동으로 열립니다. 이후에는 일반 `/admin-atlas/` 주소에서 관리자 로그인만 하면 자동으로 열립니다. 모든 원고는 검토 중이며 창작 삽화임을 표시합니다. 초기화/삭제 기능은 없습니다.
4. 장면·추리·카드를 체험하고 감상을 입력한 후 검토실로 돌아와 ‘테스트 기록 서버 확인’을 누릅니다. 캐시 표시가 아니라 인증된 HTTPS REST 재조회 결과와 비교합니다. 실패를 성공으로 표시하지 않습니다.
5. 로그아웃·재로그인, 다른 기기의 동일 관리자 로그인으로 복원을 확인합니다. 두 기기에서 감상을 동시에 편집하지 않습니다. 일반 사용자 상호 차단의 실제 계정 검증은 별도 미검증입니다.

## 검증

`node tools/test-admin-atlas.cjs /absolute/path/haeinsa-admin-review.private.json /absolute/path/setup-key.private.txt`

Playwright/Chromium이 설치된 환경에서 실행합니다. 외부 통신은 모의 처리합니다. 320·390·768·1440px에서 비로그인/비관리자의 원고 요청 0건, 주소에서 키 제거, 잘못된 키 거부(쓰기 0건), 인증 후 최초 자동 등록·자동 열기, 기존 등록 시 키 없이 로그인만으로 열기, 12장면/6문제/3카드/감상, sources, 지도·굿즈 진입 없음, 원형 SVG 화살표 중심 정렬, 별도 경로에만 쓰기, 별도 로컬 캐시, 화면 가로 넘침 없음 검증. 모의 검사는 실제 Google 로그인·현행 운영 DB 규칙·실제 기기 복원을 통과한 것으로 보고하지 않습니다. 실제 관리자 검증은 사용자가 수행해야 합니다.

검토실 이외의 기존 홈·기능·Firebase 규칙은 수정하지 않습니다. 문제 시 새 관리자 페이지 파일의 추가 커밋만 되돌리며 사용자 데이터를 삭제하지 않습니다. 운영 배포 전에 기존 main SHA를 복구 기준으로 기록합니다.

추가 검사: `node tools/test-admin-atlas-worker.cjs` — 기존 루트 서비스 워커가 이미 설치된 브라우저에서 검토실 전용 워커로 전환되고 비공개 응답이 캐시에 남지 않음을 실제 Chromium 서비스 워커로 확인했습니다. Firebase/인증은 모의입니다.

전용 등록 링크는 초기 비밀자료를 전달하는 열쇠이므로 공개하거나 공유하지 마세요. 링크를 아는 사람은 공개 암호문을 별도 복호화할 수 있습니다. 개인 진행/감상 기록은 링크가 있어도 Firebase 인증 및 소유자 권한이 필요합니다. 기존 공개 PR의 원고 노출 이력을 이 조치가 철회하지는 않습니다.
