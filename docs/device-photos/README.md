# 기기 사진 · 나의 산사 도감 · 연꽃 축하 파티

기준 main: `0816d4f`(시즌2 표시 수정 배포). 기존 개인 MY 카드는 없다는 사용자 확인 뒤 새로 추가했습니다.

## 변경 파일

- `index.html`: 기기 사진 모듈 연결, 계정 변경/로그아웃 알림, 기존 사진 업로드 경로 차단, GPS 방문 기록 저장 응답 뒤 축하 실행. GPS 거리·정확도·머무름 판정 및108고유 번호는 그대로입니다.
- `scripts/device-photos/store.js`: 계정/게스트별 IndexedDB Blob·썸네일·배경 설정, 저장 완료 확인, 계정 전환 중 작업 중단.
- `scripts/device-photos/ui.js`: 절/산 사진 추가, 기존 클라우드 사진과 함께 보기, 앨범, 백업/복원, 저장공간 안내.
- `scripts/device-photos/zip.js`: 추가 라이브러리 없는 ZIP 백업·읽기, CRC·파일 이름·용량·형식 검사.
- `scripts/device-photos/cards.js`: 개인 MY 번호,3:4수채화/내 사진 카드, PNG 합성, 개인 도감.
- `scripts/device-photos/celebration.js`, `styles/device-photos.css`: 약2.9초 Canvas·CSS 연출, 무음/선택 효과음·진동, 모션 줄이기·회전 대응·정리.
- `images/personal-cards/`: 새 배경8종의 큰/작은 WebP16개, 투명 무념스님2개. 총18개 파일이 완성됐으며 누락 없음. `CREDITS.md`, `manifest.json`에 그림 설명과 크기·SHA256을 기록했습니다.
- `sw.js`: 새 앱 셸 버전. 사용자 사진 IndexedDB를 초기화하거나 삭제하지 않습니다.
- `tests/`: 사진·백업·계정·카드·GPS 저장 응답 검증과 합성 EXIF 회전 시험 파일. 기존 테스트 fixture의 Blob URL 처리와 transaction 응답을 실제 브라우저 동작에 맞췄습니다.

## 사진 저장과 보호

새 절/산 사진은 기존 압축기를 재사용하여 긴 변1600px 이하 JPEG로 만들고 메타데이터를 제거합니다. 기본 품질82%, 결과가 큰 경우 기존 압축기의 추가 품질 조정이 적용됩니다. 선택한 원본 파일은 수정하지 않습니다. 기존 선택 제한15MB도 유지합니다.

새 DB `sansaDevicePhotos_v1`만 사용합니다. `photos`에는 사용자·장소·사진ID·등록일·썸네일, `blobs`에는 사진 Blob을 저장합니다. 일반회원·관리자·게스트 모두 같은 저장 경로입니다. 전체 사진 대신 썸네일을 조회하고 큰 사진은 열 때 읽습니다.

IndexedDB transaction 완료 후에만 “사진이 이 기기에 저장되었어요.”를 표시합니다. 권한·용량·계정 변경 오류에서는 완료로 표시하지 않습니다. Firebase에 새 이미지 파일·Base64·Blob URL을 업로드하거나 사진 메타데이터를 쓰지 않습니다. 새 모듈을 불러오지 못해도 기존 Firebase 업로드로 돌아가지 않도록 본래 업로드 함수도 차단했습니다.

기존 Cloud Storage 파일과 Realtime Database 사진 레코드는 자동 이전·삭제·변경하지 않습니다. 기존 조회·삭제·관리자 도구는 유지합니다. 기기 저장 전환 전 코드에서는 Storage 준비 및 업로드 성공이 사진 등록의 선행조건이었습니다. 새 경로에서는 그 의존을 제거했습니다. 운영 회원의 실제 실패 코드를 수집한 것은 아니므로 특정 운영 권한 오류를 원인으로 단정하지 않습니다.

회원UID와 브라우저 게스트 식별자로 접근을 구분합니다. 로그인 UID 일치 확인, 계정 변경 중 transaction 중단, Blob URL 해제, 열린 개인 사진/카드/인증서 정리를 적용했습니다. 게스트 사진은 회원 사진으로 자동 합치지 않습니다. 계정별 분리는 앱의 접근 제어이며 브라우저 안의 물리적 격리·암호화를 뜻하지 않습니다.

## 이용 위치와 백업

- 절·산 상세: 사진 추가, 이 장소의 사진 백업.
- 나의 산사노트(설정) → 이 기기의 내 사진: 전체 백업·복원·저장공간 확인.
- 순례 앨범: 기기 사진과 기존 클라우드 사진을 구분해서 표시.
- 나의 산사노트 → 나의 산사 도감: 개인 카드 보기.

백업은 실제 JPEG·썸네일·사찰ID/이름 연결 정보와 형식 버전1을 담은 표준 ZIP입니다. 추가 압축 없이 저장하여 모바일 CPU 부담을 줄였습니다. 이 앱에서 만든 백업은 다른 일반 브라우저에서도 복원할 수 있습니다. 한 파일은 최대256MB·사진1000장입니다. 큰 백업은 상세 화면에서 장소별로 나눌 수 있습니다.

복원 전 CRC·이미지 SHA256·연결 정보·형식을 확인하고 현재 계정에 병합합니다. 같은 장소의 같은 사진은 중복으로 유지하며 ID 충돌은 새ID로 분리합니다. 기존 사진을 지우지 않고 하나의 쓰기 transaction으로 완료합니다. 회원 백업은 백업한 UID로 복원해야 하며 게스트 백업은 현재 게스트 저장소로 복원할 수 있습니다.

“파일 준비/다운로드 요청”과 실제 파일이 기기에 저장됐다는 확인은 구분합니다. 사용자는 다운로드 폴더를 확인해야 합니다. 저장공간 추정과 지속성 요청은 영구 보장이 아니며 브라우저 데이터 정리 전 백업을 안내합니다. 캐시 삭제나 사용자 브라우저 초기화를 요구하지 않습니다.

## 카드와 번호

공식108수호카드는 기존 번호·그림을 사용합니다. 개인 사찰은 별도 MY001부터 시작합니다. 회원 번호는 `users/{uid}/personalTempleCards` transaction으로 저장하고 기기에도 확인된 번호를 기억합니다. 게스트 번호는 현재 게스트 IndexedDB에 보관합니다. 기존 방문·GPS·108·비밀도감 경로와 섞지 않습니다. 회원 번호의 서버 저장을 확인하지 못하면 발급 완료나 PNG 저장 가능 상태로 표시하지 않습니다.

배경과 사진 선택은 기기에 기억합니다. 불확실한 지형에는 솔숲·운해·산문을 배정하고, 바다는 명시된 해안 정보 또는 사용자의 해안 확인이 있어야 선택할 수 있습니다. 실제 특정 사찰 건축으로 오해시키지 않는 공통 창작 풍경입니다.

개인 사진은 IndexedDB에서만 읽어 무념스님·그라데이션·번호·사찰명·지역·인증일·금색 테두리를 Canvas로 합성합니다. PNG도 Firebase로 보내지 않습니다. 기존 인증서의 수동 사진 선택도 먼저 기기에 저장하고 Blob을 다시 읽어 적용합니다.

## GPS 축하

새 verified 방문ID와 저장 성공 응답이 있어야 실행합니다. 같은 UID·사찰·방문ID는 한 번만 반응하고 실패·대기·재진입·계정 전환에는 실행하지 않습니다. 개인 MY 카드와 공식108수호카드의 보상 표기를 구분합니다.

좌우 폭죽, 상단·중앙3회 폭죽, 연꽃·별·색종이, 놀람→두 손을 든 웃음, 카드 확대·금빛 효과 뒤 카드/계속 버튼을 제공합니다. 건너뛰기는 처음부터 사용할 수 있습니다. 기본 무음·자동 진동 없음이며 버튼으로 선택합니다. 지원되지 않거나 자동재생이 막혀도 카드 확인은 가능합니다.

휴대폰 입자는150개, 큰 화면220개 이하, Canvas 최대 변1600px입니다. 화면 회전에 맞춰 크기를 바꾸고 종료 시 RAF·타이머·회전 리스너·Canvas·오디오를 정리합니다. 모션 줄이기에서는 정적 화면과 즉시 사용할 수 있는 버튼으로 대체합니다.

## 검증 범위

Chromium와 WebKit에서 일반회원/관리자/게스트 저장,1600px 압축, EXIF 회전6 및 제거, 원본 보존, 새로고침 유지, A/B 분리, 로그아웃 노출 방지, 계정 전환 중 압축 취소, 용량 오류, Firebase 사진 쓰기 없음, 실제 ZIP 다운로드·새 프로필 복원·중복 병합·앨범 디코딩을 검사했습니다.

MY 번호·배경 유지·수채화/개인 사진 PNG 다운로드, 내륙의 해안 배경 제외, 약3초 연출·1회 실행·기본 무음·Canvas 정리·모션 줄이기·공식108구분, PC/휴대폰/iPad 크기·가로 회전을 검사했습니다. GPS 성공 결과는 mock으로 공급하고 실제 앱의 저장 응답 대기·저장 거절·계정 변경 경로를 검증했습니다.

기존 사진/방문/108/지도 대체 화면/코스/커뮤니티/마이페이지/서원/음악 오프라인/서비스워커/시즌 전환/비밀도감 저장 분리 검사도 수행했습니다. 테스트는 fixture를 사용했으며 운영 Firebase 데이터에 테스트 쓰기를 하지 않았습니다.

WebKit Blob 저장 검사는 일반 브라우저와 같은 영속 프로필을 사용합니다. 이 Linux WebKit의 비공개 메모리 프로필은 Blob IndexedDB 쓰기가 실패하여 정상 저장 검증 대상으로 사용하지 않았습니다. 실제 iPhone·Galaxy·iPad 실기기와 운영 계정으로 GPS/쓰기 검증을 수행한 것은 아닙니다.

## 모바일 첫 로딩

로컬 Chromium390×844@3·CPU4배 감속·SDK2초 지연으로 기준 main과3회씩 교차 측정했습니다. FCP 중앙값은640→636ms로 비슷했고 홈 비밀도감 높이는290.19px로 동일했습니다. 전체 응답 바이트의 추가량은 약57KB(약0.27%)입니다. 첫 화면의 작은 회차 썸네일은2개, 새 개인 카드 그림·비밀도감 본문 미리 요청은0개였습니다. 실제 모바일 통신망/CWV 수치는 아니며 원시 결과는 `performance.json`에 보관했습니다.
