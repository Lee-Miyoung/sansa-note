# 수채화 UI 리뉴얼 구현·검증 기록

## 기준과 변경 파일

- 최신 `origin/main` e3aaf49에서 이어서 수정했다. 과거 index.html로 되돌리지 않았다.
- `index.html`: 기존 11개 기능의 ID·이벤트를 재사용. 카드 장면·내부 제목·호흡 남은 시간·목탁 그림·부적 종이/문양 선택·사진 대체 안내를 개선. 로그인·Firebase 저장 경로·사용자 데이터 스키마·커뮤니티·현장 인증 판정·게임 점수/랭킹 규칙은 변경하지 않았다.
- `styles/wellness.css`: 이번 영역의 중복 스타일을 모아 관리. 기존의 큰 카드/작은 카드 override 묶음을 교체했다. 모바일의 중복 산 이미지와 `::after` 배경을 제거했다.
- `scripts/wellness-effects.js`: 목탁 파동·카운터·저장 피드백, 호흡 남은 시간, 음악 재생 상태 표시. 사용자 저장소에 접근하지 않는다.
- `copy/index.html`: 기존 문구·필사 저장 처리 유지. 종이색·입력창·캐릭터를 홈과 연결했다.
- `sw.js`: 새 정적 파일 캐시 버전. 다른 기능의 캐시는 삭제 대상에서 제외. localStorage·Firebase·IndexedDB 기록을 초기화하지 않는다.
- `images/brand/wellness/props/`: 기존 사용자 이미지 16개의 WebP 파생본, 총 약 864KiB. `companion-poses.webp` 약 358KiB. 원본 파일은 보존했다.
- 신규 그림 제작 사양: [wellness-art-specifications.md](wellness-art-specifications.md). 장소별 검토 대장: [place-illustration-review.md](place-illustration-review.md).

## 실제 확인한 내용

Chromium 브라우저 자동화이며, 로컬 최신 파일을 운영 도메인 URL에 라우팅했다. 외부 Firebase·사진 API는 실제 사용자 데이터를 건드리지 않도록 차단하거나 테스트 응답을 사용했다. 모바일 조작 검사는 터치/모바일 컨텍스트도 사용했다.

- 320·375·390·430·768·1440px: 11개 캐릭터 이미지 디코딩, 카드가 화면 안에 들어오는지, 글자와 캐릭터가 겹치지 않는지 검사.
- 모바일 320~430px: 메뉴 그리드 높이 합계 386px. ‘마음 쉬어가기’ 4개 한 줄 88px, 일반 수행 카드 72px, 음악 카드 64px. 사용자가 요청한 일반 수행 카드 20% 확대(60→72px)를 적용했다. 제목과 영역 간 여백은 이 합계에서 제외했다.
- PC 1440px: 메뉴 그리드 높이 합계 456px, 일반 메뉴 4열, 음악 카드 2칸.
- 320·390·768·1440px: 내부 모달 10개 실제 열기/닫기, 전환 후 화면 경계, 제목/캐릭터/닫기 버튼 충돌, 별도 필사 페이지 가로 넘침 검사.
- 320~1440px 10개 폭 및 가로 화면: 고정 상단 내비게이션 한 줄, 메뉴 접근, 활성 상태, 터치 영역 검사.
- 390·1440px 기능 조작: 목탁 클릭/Enter 및 카운터 저장, 호흡 시작·56초 안내·닫기, 고민 입력/처방 결과, 염불 카운터 저장, 발원문 작성/저장, 부적 색/문양 변경 및 Canvas 결과, 플레이리스트 곡 선택, 게임 패드 6개 조작 및 기존 최고점 보존, 필사 내용 이어쓰기와 완료 상태 보존.
- 390·1440px 사용자 기록 fixture: 선택한 절만 홈에 표시, 이름 없는 사진 메타데이터 레코드 제외, 개인 사진과 방문 노트 보존, 검증 안 된 구형 자동 사진 제외.
- 390·1440px 절/산 탐색: 실제 메뉴를 눌러 사진 로딩과 상세 화면의 캐시 재사용 검사. 사진 제공 API와 이미지 응답은 fixture를 사용했다.
- 장소 사진이 없을 때 일반 수채화 이미지임을 밝히고 장소명 표시. 사진 검색이 사용자 Firebase 데이터를 쓰지 않는지 확인.
- 배너: 구형 배경 이미지와 모바일 가상 배경을 제거한 화면을 PC/모바일에서 시각 확인. 글자 로고는 정지, 원형 로고 12초 회전, 동작 줄이기 시 회전 중지 규칙 적용.
- JS 구문·로컬 CSS 이미지 경로·git whitespace 검사.

재실행: Playwright가 설치된 환경에서 `node tests/wellness-layout.cjs`, `node tests/wellness-actions.cjs`, `node tests/home-photo-regression.cjs`. 기본 Chromium 경로는 `/usr/bin/chromium`, `CHROMIUM_PATH`로 변경 가능하다. 테스트는 격리된 브라우저 저장소에만 테스트 데이터를 작성한다.

## 확인하지 못한 항목과 제한

- 실제 아이폰 Safari/WebKit·갤럭시 Chrome·아이패드 하드웨어 검증은 하지 못했다. 현재 환경에는 Chromium만 설치되어 있다. 화면 폭/터치 에뮬레이션 검사를 실제 기기 검증이라고 보고하지 않는다.
- Firebase 실제 계정 로그인·운영 데이터 쓰기·현장 GPS 인증·실제 랭킹 서버 업로드는 실행하지 않았다. 해당 처리 코드는 유지했다.
- 실제 기기 스피커의 음질·음량·음악 자동재생 정책은 확인하지 않았다. 기존 소리 처리와 미디어 조작 경로를 유지했다.
- Wikipedia/Commons/Openverse는 이 클라우드 환경에서 실제 요청 모두 HTTP 403을 반환했다. 따라서 운영 사용자 네트워크의 외부 사진 성공률은 보장하지 않는다. API 성공/오류 fixture로 로딩·검증·대체 화면을 확인했다.
- 211개 장소의 실제 모습을 검증한 새 그림은 생성하지 않았다. 공식 자료를 확인한 뒤에만 제작/등록할 수 있도록 검토 대장을 작성했다.
- 내부 화면 두 번째 시안 이미지는 대화에서 확인할 수 없어 지시서 콘셉트로 구현했다. 전용 찻집/서재 배경, 별도 목탁채 애니메이션용 그림 등은 추가 제작 사양으로 남겼다. 기존 소품을 조합한 UI를 전용 신규 원화 제작 완료라고 보고하지 않는다.
