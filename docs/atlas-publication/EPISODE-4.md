# 제004화 · 순천 송광사 — 한 스님의 다짐이 남긴 이야기

기준 main: `4196c6929e8c7cb0a147b35d5a39be09e5c547ac`. 작업 시작 시 공개 `episodes.json`의 1·2·3화와 공개 통도사 content.js를 확인했다. 대상은 전남 순천 조계산 송광사이며 전북 완주 송광사가 아니다.

## 구현과 읽기 화면

- 독립 페이지 `/atlas/songgwangsa/`, 기존 공통 bootstrap/renderer/store/auth-loader/서비스워커를 사용한다. 새 회차용 저장 시스템이나 별도 렌더러를 만들지 않았다.
- 기존과 같은 12장면 · 6문제 · 3장 카드다. 각 부의 네 장면을 읽으면 카드를 받는다. 장면 건너뛰기나 퀴즈 오답으로 조건이 바뀌지 않는다.
- 홈은 기존 `scripts/atlas/episodes.json`에 메타데이터 한 행만 추가했다. 순서는 해인사 → 불국사 → 통도사 → 송광사다. 스와이프·화살표·페이지 표시를 재사용한다.
- 공통 읽기 화면의 ‘이전·다음’을 스크롤 영역 밖의 고정 영역으로 옮겼다. 같은 기존 prev/next 처리기를 사용하므로 읽기 완료·카드 획득·뒤로가기 로직은 유지한다. 마지막 장면은 ‘카드 보기’로 표시한다.
- 상단 ‘전체화면’은 화면을 넓히고 읽는 동안 보조 탭을 접는다. 지원되는 브라우저는 Fullscreen API도 사용한다. iOS처럼 API가 없거나 거부되는 환경에서는 뷰포트 안에서 읽기 화면을 최대로 확장한다. 브라우저 주소창까지 반드시 감춘다는 보장은 없다. ‘화면 줄이기’와 닫기로 복귀하며, 전체화면 전환은 진행 기록을 쓰지 않는다.
- 장면 전환 때 이전 그림의 재시도 타이머를 정리한다. 현재 장면 DOM을 교체하는 기존 구조를 유지한다.
- 송광사는 그림 위 ‘수채화’ 배지를 생략한다. 그림 출처는 별도 CREDITS와 역사 자료 화면에서 안내한다. 기존 회차의 그림/원고/카드 ID는 바꾸지 않았다.

지눌을 포함한 16국사는 여러 시대의 고승을 기리는 전통이다. 모두 지눌의 직접 제자이거나 같은 시대의 인물이라고 쓰지 않았다. ‘조계산 송광사’ 항목의 일부 인물은 고려 문헌에서 국사 칭호가 확인되지 않고 후대의 추모에 포함됐다는 학술적 구분도 자료 설명에 반영했다. 현재 국사전에 원본 영정 16점이 모두 그대로 남아 있다고 단정하지 않는다.

항목 사이 수선사 명칭/이주 세부 연대의 서술이 달라, 4화는 그 명칭 변경을 정확한 특정 연도에 고정하지 않는다. 오늘의 전각·우화각을 지눌 당시의 건축물 모습 그대로라고 설명하지 않는다. 창건 설화나 신비한 전승을 확인된 사건으로 추가하지 않았다. 그릇을 씻는 공동생활 장면은 사료에 기록된 특정 사건이 아니라는 점을 역사 자료에서 밝힌다.

사찰 공식 홈페이지는 환경 프록시에서 접속되지 않았다. 위 백과사전의 원문 대조를 통해 필요한 내용을 검토했으며, 접근되지 않은 사이트를 확인 완료 출처로 표시하지 않았다.

## 그림과 출처

표지 1장, 본문 12장면, 카드 3장의 AI 창작 수채화를 제작하고 실제 사진과 비교했다. 시대별 인물 모습은 실제 초상의 복원이 아니다. 자연광·실내·산길·대화·일하는 장면 등 구도를 구분했고, 꽃 장식이나 출처 배지를 넣지 않았다.

- 대웅보전: 한국학중앙연구원 ‘순천 송광사 대웅전 정면’(Commons의 공공누리 제1유형 표시). 넓은 단층 정면 5칸, 큰 팔작지붕, 문과 기둥, 석축·가운데 계단의 비례를 비교했다.
- 국사전: ‘순천 송광사 국사전 01’(Commons 업로드 출처 Korea Copyright Commission, 저자 미상, public domain 표시). 낮은 맞배지붕·격자문·기단을 비교했다. 정면 네 칸의 안내 원문도 대조했다.
- 우화각: Oadde, ‘松廣寺 Korean Temple Songgwangsa by Oadde 05’, 2018-06-23, CC BY-SA 4.0. 삼청교의 낮은 단일 아치 위 긴 지붕 통로와 인접 건물 연결을 비교했다. 숲속의 독립 누각인 청량각을 우화각으로 사용하지 않았다.
- 캐릭터와 그림체: 기존 통도사 표지 및 그 그림 이용 안내에 기록된 기반 그림의 조건을 이어간다. 새 그림은 CC BY-SA 4.0으로 제공한다.

초기 활동 시기의 지눌이 지나치게 나이 들어 보이던 두 그림은 1182년·1190년의 나이에 맞는 성인 모습으로 수정했다. 원본 PNG는 `/workspace/generated_images/`에 보존했다. 배포에는 `atlas/songgwangsa/images/`의 WebP 32개(16장 × 2크기)만 사용한다. 출처 링크·저자·가공 및 이용 조건은 `/atlas/songgwangsa/CREDITS.html`, 파일 크기·SHA-256은 `images/manifest.json`에 기록했다.

## 홈 성능과 이미지 메모리

홈 `index.html`은 2,219,427 bytes로 변경 전과 같고 SHA-256도 `7b69edfbb5c7b33ce022f51f0ed7af9d01032c1b50e84fac9b0f8beb9c2cd689`로 동일하다. 목록은 줄바꿈 포함 572 → 782 bytes(+210 bytes). 초기 썸네일 URL 2개는 그대로이며 새 본문·퀴즈·카드·공통 읽기 코드가 홈에서 요청되지 않는다. 가상 12회차에서도 같은 조건을 검사했다.

표지 소형 43,296 bytes, 본문 소형 31,546~54,618 bytes, 카드 소형 최대 84,552 bytes다. 큰 그림을 포함한 활성 32파일 전체 저장 용량은 4,266,322 bytes이며 초기 전송량이 아니다. 독립 회차 방문 전에는 목록의 표지 썸네일 외에 4화 원고·장면·카드를 받지 않고, 랜딩에서는 표지만 받는다. 읽기 시작 때 다른 11장면을 프리로드하지 않는다. 이 장면 단위 요청이 지연 로딩 역할을 하며 현재 표시할 그림은 즉시 요청한다. 휴대폰은 높은 DPR에서도 작은 WebP를 먼저 사용한다.

통제된 로컬 홈 측정: 390×844 Chromium, CPU 4배 감속, 빈 SDK 응답 2초 지연, 외부 폰트 차단, 서비스워커 차단. 다른 브라우저 검사가 동시에 실행된 첫 측정은 변동이 커서, 검사 종료 뒤 같은 조건으로 3회차/4회차를 번갈아 재측정했다. 최종 FCP는 3회차 552/480/576ms, 4회차 480/428/448ms, DOMContentLoaded는 각각 849/835/858ms와 789/733/775ms다. 이를 4화 추가가 속도를 개선했다는 인과 증거로 해석하지 않는다. 실제 아이폰·Firebase·모바일망·운영 Core Web Vitals 수치가 아니다. 확실한 구조적 결과는 홈 HTML 동일, 메타데이터 +210 bytes, 초기 이미지 수 동일, 홈의 4화 파일 요청 0개다.

120회 빠른 장면 교체 후 iPhone/iPad/Galaxy 에뮬레이션에서 읽기 화면 1개·현재 장면 그림 1개를 유지했다. Galaxy Chromium GC 후 DOM 노드 209→206, 이벤트 리스너 51→51이었다. 이는 DOM·리스너 누적 검사이며 실제 기기 전체 메모리/브라우저 이미지 캐시의 MB 측정은 아니다.

## 기록 보존과 검사

4화의 로컬 키는 `sansaSecretAtlas_v1:<owner>:songgwangsa-004`, 계정 경로는 `users/<uid>/secretAtlas/songgwangsa-004`다. 기존 저장 버전·저장 코드·1~3화 키는 유지했다. Firebase 규칙·운영 데이터·순례/사진/108 수호카드/지도/GPS 코드는 변경하지 않았다. 실제 사용자 데이터의 읽기·쓰기·삭제나 마이그레이션은 수행하지 않았다.

- `tests/atlas-reading-controls.cjs`: PC Chromium, iPhone Safari WebKit, iPad Safari WebKit, Galaxy Chrome Chromium 에뮬레이션에서 1~4화의 고정 버튼·화면 확대·줄이기·닫기·건너뛴 카드 미획득. 미지원/거부된 Fullscreen API 대체 동작.
- `tests/atlas-reader-resources.cjs`: 새 회차 랜딩/첫 장면의 비선로딩, 고밀도 휴대폰 소형 이미지, 120회 장면 교체의 DOM 누적, 네이티브 Chromium 전체화면 진입/이탈과 진행 기록 동일성.
- `tests/atlas-episodes.cjs`: 320/390/412/768/820/1440px에서 1~4화 각각 12장면·6답·3카드·메모 복원·뒤로/닫기·이미지, 홈 스와이프/버튼, 모의 A/B 계정 분리 및 기존 순례/108 fixture 보존.
- `tests/songgwangsa-mobile.cjs`: WebKit 390/820px의 4화 전체 흐름, 정상 형식의 기존 3회차 카드·위치·메모 복원, A/B/guest 분리, 완주 송광사 인증이 순천 송광사 인증으로 적용되지 않음, 잘못된 회차 원고 차단.
- `tests/atlas-home-catalog.cjs`: Chromium 및 WebKit에서 실제 4회·가상 12회, 초기 2개 썸네일, 마지막 회차 이동, 본문 비선로딩, 오류 폴백, 공개 Web 설정 동일.
- `tests/atlas-art-recovery.cjs`: Chromium/WebKit의 1~4화 일시적 이미지 오류·소형 누락·전체 오류·수동 복구·응답 지연 복구.
- `tests/mobile-navigation-worker.cjs`: 실제 워커 캐시가 있는 상태에서 3회 목록을 읽은 뒤 4회 목록을 즉시 다시 읽음.
- `ATLAS_EPISODE_PATH=/atlas/songgwangsa/ node tests/tongdosa-transport.cjs`: 실제 루트 서비스워커→새 회차 워커 전환, 이전 런타임 캐시 우회, 홈 HTML 재다운로드 없음.
- `SANSA_BROWSER=webkit node tests/atlas-offline-startup.cjs`: 1~4화에서 외부 Firebase SDK가 계속 대기해도 독립 읽기 가능.

브라우저 검사에는 모의 인증/데이터를 사용했다. 실제 PC/iPhone/iPad/Galaxy 기기를 직접 검사한 것은 아니며, 실제 계정 로그인/기기 GPS/운영 저장까지 검증한 것으로 해석하면 안 된다.
