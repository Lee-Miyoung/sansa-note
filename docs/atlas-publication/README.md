# 비밀도감 홈 공개 설정

사용자가 선택한 비공개 범위는 **홈에서 숨기기**입니다. `/atlas/` 본문은 누구나 직접 열 수 있습니다. 이미 공개한 파일을 비밀 자료로 취급하지 않습니다. 관리자 검토실 `/admin-atlas/`의 인증·원본·키·테스트 기록은 변경하지 않습니다.

## 운영자 최초 1회 설정

현재 운영 규칙에는 새 공개 설정 경로가 없으므로, 웹 배포만으로 관리자 버튼의 서버 저장 권한이 생기지 않습니다.

1. Firebase 콘솔의 운영 프로젝트 `travel-diary-c0676` → Realtime Database → 규칙을 엽니다.
2. 현재 규칙을 먼저 복사해 보관하고, `production-with-publication.rules.json`과 비교합니다. 이 초안의 기준은 사용자가 제공한 운영 규칙입니다. 현재 콘솔이 달라졌다면 전체를 덮어쓰지 말고 `rules.fragment.json`의 새 노드만 `rules.shared` 아래에 추가하세요.
3. 새 경로 규칙 적용 후 산사노트 관리자 모드 → **산사 비밀도감 · 해인사** → **설정 다시 확인**을 누릅니다. 이후 **홈에 공개 / 홈에서 비공개**로 선택합니다.

기존 권한은 유지하고, 새 `shared/secretAtlasPublication/haeinsa-001` 경로만 추가합니다. `.read: true`는 공개 여부 boolean/시간에만 해당합니다. 쓰기는 실제 Google 인증·이메일 인증을 마친 기존 관리자에게만 허용하며 삭제·잘못된 형식·임의 필드는 거절합니다. `.validate`로는 삭제를 제한할 수 없어 `.write`의 `newData.exists()`로 삭제를 제한합니다. 다른 기능의 설정 경로를 재사용하지 않습니다.

코덱스는 운영 규칙을 적용하지 않았고 실제 Firebase 데이터를 쓰거나 삭제하지 않았습니다. 공개 기본값은 사용자가 승인한 `true`입니다. 새 설정을 읽을 권한이 아직 없으면 공개 기본값을 유지하되 관리자 제어는 비활성화하고 최초 설정 안내를 표시합니다. 네트워크 장애 시 이미 확인한 값은 유지합니다. 저장 완료는 쓰기 승인 후 서버 재조회 값이 맞을 때만 표시합니다.

## 기존 데이터 보호

- 공개 페이지의 게스트 저장소: `sansaSecretAtlas_v1:guest:haeinsa-001`. 관리자 검토실 로컬 저장소와 분리.
- 로그인 저장 경로: `users/{현재 uid}/secretAtlas/haeinsa-001`만 쓰기. 기존 `destinations`는 읽기 전용으로 인증 표식 참고. 순례·사진·일기·108 수호카드 경로 쓰기/삭제 금지 어댑터 적용.
- 게스트 기록과 계정 기록은 자동 병합하지 않습니다. 계정별 저장소와 리스너를 분리합니다.
- 관리자 검토 진행 기록을 공개 페이지 기록에 복사하거나 초기화하지 않습니다.

## 공개 원고

기존 검토실에서 쓰는 짧은 사실·창작 대화·질문 버전을 공개했습니다. 12장면/6문제/3카드와 기존 그림을 유지하며 지도/굿즈 화면은 포함하지 않습니다. 모든 출처 상태는 `pending` 그대로입니다. 공개 승인을 역사 검증 완료로 바꾸지 않았습니다. 각 화면에 검토 중/삽화·대사 창작 안내를 표시합니다.
