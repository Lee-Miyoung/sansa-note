# 제003화 통도사 — 불상이 없는 법당의 비밀

## 구조 검증을 먼저 진행

기준 main은 `94ff405`였다. 1·2화의 본문/그림을 바꾸지 않고, 먼저 공통 로딩 구조와 홈 목록을 정리했다. 회차 2개 및 가상 12개를 사용한 Chromium·WebKit 검사, 기존 1·2화의 12장면/퀴즈/카드/기록/계정 분리, 홈 사진/순례/공개 설정, 인증 지연 중 홈 진입 검사를 통과한 뒤 3화 제작을 시작했다.

- 1화 `/atlas/`, 2화 `/atlas/bulguksa/` 경로를 유지했다. 3화는 `/atlas/tongdosa/`다.
- 홈 `index.html`에는 회차별 본문이나 카드 마크업을 넣지 않는다. 고정된 슬라이드 컨테이너와 링크 폴백만 둔다. 제목·링크·썸네일 주소는 `/scripts/atlas/episodes.json`에 둔다.
- 3화 추가 전후 홈 HTML의 SHA-256이 동일했다. 구조 정리 전 홈은 2,220,774 bytes, 정리 후는 2,219,427 bytes다. 공통 목록 렌더러의 고정 비용은 별도로 있으므로 전체 홈 트래픽이 같은 양만큼 줄었다는 뜻은 아니다.
- 실제 3회차 목록은 572 bytes. 2회차 목록 381 bytes에서 191 bytes 증가했다. 최초에는 가까운 썸네일 2개만 URL을 부여한다. 3화 썸네일은 44,566 bytes이며 인접 회차로 이동할 때 사용한다. 홈페이지에서 3화 본문·퀴즈·수집 카드 요청이 없는 것을 검사했다.
- 12회로 확장해도 본문 프리로드가 없고, 페이지 폭이 넘치지 않으며 슬라이드·점·버튼이 동작한다. 점 목록은 작은 화면 안에서 가로 스크롤된다. 목록 요청이 실패하면 기존 1화의 일반 링크가 남는다.
- 서비스워커는 목록을 오래된 캐시로 고정하지 않고 새 목록을 읽는다. 실제 워커 검사에서 2회 목록을 읽은 뒤 3회 목록으로 바뀌는 것을 확인했다.
- 공통 bootstrap/store/renderer의 2회차 전용 분기를 경로·회차 ID·콘텐츠 메타데이터로 대체했다. 1화의 기존 `temple` 필드와 ID/저장 키도 호환한다.
- 로그인 설정을 찾으려고 홈 HTML 전체를 다시 받던 요청을 동일한 공개 Web 설정 316 bytes로 바꾸었다. 6개 값은 기존 홈 설정과 모두 같으며 자동 검사한다. 사용자 비밀 키를 새로 요청하거나 기록하지 않는다.
- 1·2화 HTML에서는 외부 인증 SDK를 비차단 로더로 바꾸고 공유 런타임 URL을 갱신했다. 이야기 문장·그림은 그대로다. 독립 읽기는 계정 서비스 응답을 기다리지 않는다. 실제 루트→atlas 워커 전환에서 옛 런타임 캐시도 우회한다.

## 3화 이야기와 그림

12장면, 역사 추리 6문제, 4장면마다 받는 3장 카드 형식이다. 장면 본문은 각각 3문단, 총 135~181자다. 기존 색상·볼드 강조를 사용한다. 핵심은 대웅전과 금강계단의 관계, 진신사리의 신앙적 의미, 자장율사의 사리 전래 전승과 계율이다.

‘불상이 없다’를 통도사의 모든 전각에 적용하지 않는다. 자장율사의 사리 전래는 전승으로 명시한다. 사리의 기원을 과학적으로 입증했다거나, 현재 건물 전체가 신라 때 모습 그대로라는 식으로 설명하지 않는다. 실제 발언을 창작 인용하지 않는다. 출입·촬영은 방문 당시 현장 안내에 따르도록 한다.

창작 표지 2개 크기와 본문 12장면/카드 3장의 원본·소형 SVG, 총 32개 이미지 파일의 합은 379,664 bytes다. 이는 전체 페이지 전송량이 아니라 그림 파일 합계다. 본문 그림은 경량 개념 삽화이며 실측 복원도·당시 현장 사진·실제 유물 사진이 아니다. 그림 설명과 재사용 조건은 `atlas/tongdosa/CREDITS.html`, 크기/해시는 `images/manifest.json`에 있다.

## 기록 보존과 검사

기존 localStorage 키 및 `users/<uid>/secretAtlas/haeinsa-001`, `.../bulguksa-002`를 유지했다. 새 회차만 `tongdosa-003`을 사용한다. 순례·사진·108 수호카드에 쓰는 경로와 Firebase 규칙은 변경하지 않았다. 실제 운영 개인 데이터 읽기/쓰기/삭제나 데이터 이전은 수행하지 않았다.

- `tests/atlas-home-catalog.cjs`: Chromium/WebKit, 390/820/1440px에서 실제 3회 및 가상 12회, 초기 썸네일 수, 전체 슬라이드, 비프리로드, 실패 폴백, 행당 경량 스키마와 공개 설정 일치 통과.
- `tests/atlas-offline-startup.cjs`: 1·2·3화의 외부 SDK가 계속 대기해도 독립 읽기 가능. Chromium으로 1·2화, WebKit으로 1·2·3화 검사. 실제 오프라인 파일 캐시 보장을 의미하지 않는다.
- `tests/atlas-episodes.cjs`: 320/390/412/768/820/1440px에서 3회 모두 12장면/6문제/3카드/메모 복원/뒤로/닫기/그림 디코딩 통과. 모의 계정 A/B와 회차별 저장 경로 분리, 새 회차가 기존 회차 기록을 바꾸지 않음도 통과.
- `tests/tongdosa-mobile.cjs`: WebKit 390/820px, 12장면과 네 장면 단위 카드 획득, 6문제, 메모·카드 복원, 1·2화의 원래 기록 바이트 보존 통과. 다른 회차 콘텐츠를 잘못 제공하면 시작하지 않는 것도 검사했다.
- `tests/tongdosa-transport.cjs`: 실제 서비스워커에서 구 런타임 캐시가 있어도 3화가 열리고 전용 워커로 전환되며, 홈 HTML을 받지 않음 통과.
- `tests/mobile-startup-resilience.cjs`, `tests/home-photo-regression.cjs`, `tests/public-atlas-worker.cjs`, `tests/atlas-publication-ui.cjs`, `tests/navigation-history.cjs`, `tests/mobile-startup.cjs`, `tests/mobile-navigation-worker.cjs` 통과.
- 통제 성능 재현 3회: FCP 392/468/456ms, DOMContentLoaded 760/729/769ms. 390×844, CPU 4배 감속, 빈 SDK 응답에 2초 지연, 로컬 파일·외부 폰트 차단 조건이다. 실제 휴대폰/실제 Firebase/운영 Core Web Vitals 수치가 아니다. 워커 설치 미디어 요청은 0개다.

## 확인하지 못한 범위

실물 아이폰 Chrome의 Google 검색 클릭 경로 및 실제 사용자 로그인/운영 3화 저장은 미검증이다. WebKit 결과를 실기기 결과로 간주하지 않는다.

통도사 공식 홈페이지, 국가유산포털, 한국민족문화대백과사전, UNESCO의 공식 원문 접속은 환경 프록시 403으로 차단되어 전체 대조를 마치지 못했다. 필요한 도메인을 환경 설정 초안에 추가했지만 초안 저장을 런타임 적용으로 간주하지 않는다. 출처의 확인 상태는 `pending`이며 본문 자료 목록에도 표시한다. 창건 연도·전래의 세부 경위 등 확인하지 못한 상세는 단정하지 않았다. 위의 기능·성능 통과를 역사 원문 검증 완료로 해석하면 안 된다.
