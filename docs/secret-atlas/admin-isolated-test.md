# 기존 관리자 Google 계정으로 격리 테스트

운영 사이트나 운영 Firebase에는 적용하지 않습니다. 새 Firebase 프로젝트에서 기존 관리자 Google 계정 하나로 먼저 확인합니다. 비밀번호·인증코드·ID 토큰·서비스 계정 키를 전달할 필요가 없습니다.

## 현재 준비 상태

- 독립 테스트 페이지: `tools/admin-atlas-test/`. 운영 `index.html`, 서비스 워커, 로그인 후 프로필 처리 코드를 실행하지 않습니다.
- 운영 비밀도감의 `store.js`를 수정 없이 복사하여 저장·복원 동작을 검사합니다. 역사 이야기 전체 화면의 시각·내용 검증용 페이지는 아닙니다.
- 전체 통합 규칙을 그대로 복사합니다. 기존 운영 규칙을 변경하거나 업로드하지 않습니다.
- 운영 프로젝트·운영 Web API 키·혼합 설정을 거부합니다. API 키 소속 프로젝트 확인 후 Firebase를 초기화하고, Google 토큰의 프로젝트·발급자·인증된 관리자 이메일을 확인한 뒤 저장 모듈을 연결합니다.
- 페이지의 데이터 접근은 테스트 UID의 비밀도감 경로와 기존 방문 참조 읽기로 제한합니다. 프로필·108 카드·방문 기록에는 쓰지 않습니다. 새 프로젝트에 운영 데이터를 복사하지 않습니다.
- 서버 확인 버튼은 로컬 캐시가 아니라 테스트 DB REST 응답을 다시 읽어 현재 기록과 비교합니다. 불일치·오류는 성공으로 표시하지 않습니다. 삭제·초기화 버튼은 없습니다.

## 사용자가 먼저 할 일: 새 프로젝트 생성

1. Firebase 콘솔에서 **새 프로젝트**를 만드세요. ID는 `sansa-atlas-test-`로 시작해야 합니다. 예: `sansa-atlas-test-miyoung`. 운영 `travel-diary-c0676`은 선택하지 마세요. Analytics는 필요 없습니다.
2. 새 프로젝트에서 Web 앱을 등록하세요. 프로젝트 설정 → 내 앱의 공개 `firebaseConfig` 값을 **JSON 형식** 파일로 PC에 저장하세요. 예: `stage-web-config.json`. 서비스 계정 JSON이 아닙니다. 필요한 필드는 `apiKey`, `authDomain`, `databaseURL`, `projectId`, `messagingSenderId`, `appId`입니다. 이 파일을 채팅이나 GitHub에 올릴 필요는 없습니다.
3. 새 프로젝트의 Authentication → Sign-in method에서 **Google만** 활성화하세요. 지원 이메일은 본인 이메일을 선택하세요. 운영 로그인 설정은 건드리지 않습니다. 익명 로그인·이메일 회원가입을 활성화하지 마세요.
4. 새 프로젝트에 Realtime Database를 **잠금 모드**로 생성하세요. 기본 인스턴스만 사용합니다. 생성 후 설정 JSON에 실제 Database URL을 넣으세요. 테스트 모드의 공개 읽기·쓰기를 선택하지 마세요.
5. Authentication의 승인된 도메인에 `<새프로젝트ID>.web.app`을 확인·추가하세요. 기본 `<새프로젝트ID>.firebaseapp.com`도 유지하세요. 프로젝트 이름과 URL을 다시 확인하세요.

같은 Google 계정이 새 프로젝트의 Auth에 처음 등록되는 것은 정상입니다. 운영 Auth 계정·UID·기록을 이동하거나 수정하는 작업이 아닙니다. 새 프로젝트에는 과금/할당량이 별도로 적용될 수 있습니다.

## 독립 사이트 생성 및 테스트 프로젝트에만 업로드

PC에 Git, Node.js 및 Firebase CLI가 있어야 합니다. PR #1 브랜치의 최신 코드를 받으세요. 저장소 루트에서 실행합니다.

```sh
node --test tools/admin-atlas-test/safety.test.cjs tools/admin-atlas-test/store.test.cjs
node tools/admin-atlas-test/prepare.cjs /absolute/path/stage-web-config.json /absolute/path/NEW-atlas-stage
```

Windows PowerShell에서는 실제 경로를 따옴표로 감싸고 `C:/...`처럼 지정할 수 있습니다. 출력 폴더는 저장소 밖의 **존재하지 않는 새 폴더**여야 합니다. 생성된 `build-manifest.json`에는 규칙과 저장 모듈의 SHA-256이 기록됩니다. 생성물은 GitHub에 커밋하지 마세요.

출력 폴더로 이동한 뒤 `.firebaserc`와 `public/stage-config.json`의 프로젝트가 새 테스트 프로젝트인지 확인하세요. Firebase CLI에 본인 Google 계정으로 직접 로그인하세요. CLI 인증정보를 공유하지 마세요.

```sh
cd /absolute/path/NEW-atlas-stage
firebase login
firebase deploy --only hosting,database --project sansa-atlas-test-miyoung
```

명령의 프로젝트 ID를 **실제로 생성한 새 테스트 ID**로 바꾸세요. 운영 ID를 넣지 마세요. 이 명령은 새 프로젝트의 잠금 규칙을 통합 규칙으로 바꾸고 독립 테스트 페이지만 Hosting에 올립니다. 저장소 루트에서 deploy하지 마세요. 현재 작업에서는 이 명령을 실행하지 않았습니다.

테스트 주소: `https://<새프로젝트ID>.web.app`. 휴대폰과 PC에서 동일한 HTTPS 주소를 사용하세요. 실제 프로젝트가 아직 없으므로 현재 공유 가능한 테스트 주소는 없습니다.

## 관리자 계정 검증 순서

1. PC에서 테스트 주소를 열고 화면에 **새 테스트 프로젝트 ID와 DB URL**이 표시되는지 확인하세요. 기존 관리자 `song4mi12@gmail.com`으로 Google 로그인합니다. 프로젝트 확인 실패 시 진행하지 마세요.
2. 장면 4를 선택하고 감상에 식별하기 쉬운 테스트 문장을 입력하세요. ‘저장 후 서버에서 직접 확인’을 눌러 **서버 기록 일치 확인**과 시간을 확인합니다. 로컬의 `cloud` 표시만으로 통과시키지 마세요. 초기 동기화 중이면 잠시 후 다시 누르세요.
3. 장면 1~4를 차례로 선택해 각각 ‘이 장면 완료 기록’을 누르세요. 첫 카드가 1장 생기는지, 같은 장면을 다시 완료해도 카드가 늘지 않는지 확인합니다. 5~8, 9~12도 반복하면 총 3장입니다. 서버 확인을 다시 누르세요.
4. 서버 확인 후 로그아웃 → 같은 계정으로 재로그인합니다. 위치·감상·완료 장면·카드가 복원되는지 확인합니다. 페이지 새로고침도 확인하세요. 서버 확인 실패 시 페이지는 로그아웃을 보류합니다.
5. 휴대폰에서 같은 테스트 주소로 로그인합니다. PC의 감상과 진행이 복원되는지 확인하고, 감상을 변경해 서버 확인 후 PC에도 반영되는지 확인합니다. 두 기기에서 동시에 같은 감상을 편집하지 마세요. 감상은 마지막 수정 시각 기준 병합입니다.
6. 결과만 공유하세요: 기기·브라우저, 로그인 성공 여부, 위치·감상·카드 복원 여부, 오류 화면 문구. 비밀번호·인증코드·토큰·실제 개인 기록은 보내지 마세요.

이 페이지는 실제 GPS 인증을 생성하지 않습니다. 새 DB에는 운영 방문 기록이 없으므로 현장 인증 복원은 여기서 미검증입니다. 운영 기록을 복사하거나 가짜 GPS 인증을 만들지 마세요.

## 검증 결과와 남은 범위

- 로컬 자동 검사 5개 통과: 설정 격리·혼합 설정 거부, Google 토큰 조건, 허용 경로 및 계정 변경 시 차단, 전체 규칙/저장 모듈의 동일 복사, 실제 저장 모듈을 이용한 모의 서버의 두 기기·재로그인·감상·카드 중복 및 기존 경로 보존.
- Chromium 모의 브라우저 검사: 320·390·768·1440px에서 로그인 → 입력 → 서버 비교 → 로그아웃 → 재로그인 복원 및 가로 넘침 없음 확인. `node tools/admin-atlas-test/browser-smoke.cjs`로 실행합니다(Playwright/Chromium 필요). 외부 통신은 전부 모의 응답으로 대체합니다.
- 모의 서버/브라우저 테스트는 실제 Google 로그인·Firebase 서버·실제 기기 결과를 대신하지 않습니다.
- 통합 규칙 에뮬레이터는 별도 GitHub Actions 실행에서 14/14 통과: https://github.com/Lee-Miyoung/sansa-note/actions/runs/39097670189 . 이번 테스트 페이지의 실계정 검증과 구분합니다.
- 실제 관리자 Google 로그인, 실 DB 저장, 실제 휴대폰/PC 복원: **사용자 실행 대기**.
- 일반 사용자 간 읽기 차단: **관리자로 실검증 불가**. 현행 관리자 전체 읽기 권한이 유지되므로 별도 일반 사용자 검증 항목으로 남깁니다. 두 테스트 계정을 지금 요구하지 않습니다.
- 운영 DB·운영 사이트·기존 사용자 기록에는 접근하거나 변경하지 않았으며 PR 병합/운영 배포도 하지 않았습니다.
