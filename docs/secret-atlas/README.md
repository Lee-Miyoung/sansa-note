# 무념스님의 산사 비밀도감 — 해인사 제001화

**상태: 로컬 검토판. 역사 원문 검증·운영 Firebase 보안 검증 전이므로 정식 공개하지 않음.**

2026-10-18 기준 `main`의 `f24a701`을 바탕으로 기존 기능을 보존하며 독립 모듈을 구현했다. UI 동작 검증과 역사 내용 검증은 별개의 완료 조건이다. 현재 원고는 공식 자료 대조를 끝내지 못했으며 완성된 역사 교육 콘텐츠로 보증하지 않는다.

## 로컬에서 보기

```sh
python3 tools/preview-secret-atlas.py
```

`http://127.0.0.1:4173`에서 홈의 ‘산사 비밀도감’을 누른다. 프리뷰 서버는 메모리에서만 검토 플래그와 게스트 시작을 삽입한다. 저장소의 운영 HTML을 바꾸거나 기존 도메인의 브라우저 저장 공간을 사용하지 않는다. 일반 URL 쿼리나 localStorage 값으로 검토 모드를 켤 수 없다. 프리뷰 서버를 운영 서버로 쓰지 않는다.

운영 환경에서는 `content.js`의 `published`와 모든 출처의 `status === 'verified'`가 함께 충족되어야 읽기가 열린다. 현재 둘 다 미충족이다. 배포 대신 Draft PR로 검토한다.

## 시안과 비교

크림·한지·세이지·금빛 테두리, 전통 수채화, 무념스님, 둥근 버튼, 카드/노트 구성을 반영했다. 시안을 잘라 사용하지 않고 새 원화 17종과 개별 UI를 제작했다. 휴대폰은 단일 패널, 큰 화면은 읽기 폭 제한과 카드 상세 2열을 사용한다. 카드 목록은 작은 휴대폰에서 2열로 바꾸어 읽기 크기를 유지한다.

지도는 역사적 근거가 미검증인 운송 장면이나 경로선 대신 장소 선택과 자료 설명을 제공한다. 원화는 창작 그림이며 실제 사찰의 실측 복원도와 같다고 주장하지 않는다. 화면 하단의 자료 검토/저장 안내는 시안에 없는 상태 표시다. 굿즈는 제작 콘셉트이며 구매할 수 없다.

## 파일과 구조

- `scripts/secret-atlas/content.js`: 장면·문제·카드·출처·공개 게이트. 원고 전체는 검토 대기.
- `scripts/secret-atlas/store.js`: 사용자별 정규화·로컬 저장·Firebase 연결·동기화·카드 원자적 최초 획득.
- `scripts/secret-atlas/app.js`: 10개 화면, 기존 상세 연결, 음성 읽기, 지도 탐색, 기록 입력.
- `styles/secret-atlas.css`: 기능 ID 범위 안에서만 스타일 적용.
- `images/secret-atlas/`: 웹용 WebP와 480px 반응형 파생본. `originals/`에 17개 개별 PNG 원본.
- `scripts/navigation.js`: 공통 탐색 상태에 비밀도감 어댑터를 추가. 감상 본문은 공통 탐색 스냅샷에 복제하지 않음.
- `index.html`, `sw.js`: 모듈 로드와 정적 캐시 버전 연결. 기존 기능 구현을 교체하지 않음.
- `firebase/secret-atlas.rules.fragment.json`: 기존 규칙에 검토 후 병합할 규칙 조각. 운영 규칙을 덮어쓰는 파일이 아님.
- `tests/secret-atlas*.cjs`, `tools/preview-secret-atlas.py`: 검증과 로컬 검토 도구.

원화 제작 사양은 [art-plan.md](art-plan.md), 크기·파일별 해시는 [asset-manifest.json](asset-manifest.json)에 있다. 장면·표지 원본은 1536×1024, 카드 원본은 1024×1536이다. 카드는 300dpi 기준 약 8.7×13cm 원본이며 더 큰 인쇄물은 고해상도 재제작/인쇄 교정이 필요하다. 모든 그림이 준비되었지만 역사 건물·도구 표현의 자료 대조는 미완료다.

## 사용자 데이터와 Firebase

새 데이터 경로:

```
users/{auth.uid}/secretAtlas/haeinsa-001/
  version, position { scene, at }, completed/{1..12}
  answers/{q1..q6} { selection, correct, at, attempts }
  cards/{001..003}: 최초 획득 시각
  note { text, at }, lastReadAt
  fieldVerification { templeId, visitId, at }
```

- 기존 destinations·visits·108 카드·일기·앨범·커뮤니티 경로에 새 모듈이 쓰지 않는다.
- 계정은 실제 Firebase `auth.currentUser.uid`와 앱의 `currentUid`가 일치할 때만 선택한다. 게스트는 별도의 기기 저장을 쓴다. 계정 전환 시 이전 리스너와 인증 상태를 해제한다.
- 로컬 키는 `sansaSecretAtlas_v1:{uid|guest}:haeinsa-001`, 전송 대기 패치는 별도의 `:pending` 키다. 게스트/다른 계정의 기록을 자동 병합하지 않는다.
- 장면과 답안을 필드별로 갱신한다. 카드 시각은 transaction으로 최초 값만 보관한다. 감상/이어 읽기는 수정 시각이 더 최신인 쪽을 채택한다. 전송 실패 패치를 기기에 보관하고 재연결 시 재시도한다.
- 인증 상태는 새 플래그를 임의로 신뢰하지 않는다. 현재 계정의 기존 destinations를 읽어 해인사 방문의 `verified === true`를 확인한다. 오래된 계정의 메모리 데이터는 재사용하지 않는다.
- 규칙 조각은 본인 UID만 읽기/쓰기, 데이터 형태·최대 길이·장면 범위·카드 완료 조건·획득일 변경 금지·실제 기존 방문 참조를 검사하도록 작성했다.

**운영 보안 규칙 조회/배포 및 실제 Firebase 계정 E2E는 하지 못했다.** 기존 상위 경로에 공개 `.read`/`.write`가 있으면 하위 규칙으로 접근 허용을 취소할 수 없다. 현행 전체 규칙을 검토하고, 조각을 병합한 규칙을 에뮬레이터에서 통과시킨 뒤 공개해야 한다. 규칙 조각만 있다고 운영 권한이 보장된다고 주장하지 않는다. 기존 verified 기록의 신뢰도는 기존 인증 체계에 따른다.

## 역사 검증 현황: 공개 차단 사유

우선순위에 맞춰 국가유산포털·국사편찬위원회·UNESCO·한국민족문화대백과 원문 접근을 시도했으나 환경의 네트워크 프록시가 `Tunnel connection failed: 403 Forbidden`을 반환했다. 확장 권한 재시도도 동일하게 실패했다. 성공적으로 열어 검증한 공식 원문은 **0건**이다.

따라서 출처 링크를 원문 확인 완료처럼 표시하지 않는다. `content.js`의 모든 출처는 `pending`이며 정확한 실록 기사 ID와 수종 원 논문도 확인 대기다. 목록은 **대조할 자료 목록**이고 검증을 마친 인용 목록이 아니다.

- 국가유산포털: 합천 해인사 대장경판·장경판전. 항목 링크/제작 시기 대조 필요.
- [UNESCO 세계유산 장경판전](https://whc.unesco.org/en/list/737/): 건축·보존·세계유산 연도 대조 필요.
- [UNESCO 세계기록유산](https://www.unesco.org/en/memory-world): 대장경판 및 제경판 개별 원문과 2007년 등재 대조 필요.
- [국사편찬위원회 조선왕조실록](https://sillok.history.go.kr/): 태조 7년(1398) 관련 기사, 선원사·지천사 표기·날짜·원문 범위 확인 필요.
- [한국민족문화대백과사전](https://encykorea.aks.ac.kr/): 초조/재조, 강화 대장도감·남해 분사도감 대조 필요.
- 목재 수종 연구: 원 논문과 조사 표본 확인 필요. 수종 비율은 원고·문제·지도 어디에도 넣지 않음.

12장면 모두 검토 대기다. 수종·이운·중수 연대·보존 원인·세계유산/기록유산 구분을 대조하고, 출처별 정확한 URL/자료명/확인 범위/확인일을 기록한 뒤 공개 게이트를 해제해야 한다. 특히 장경판전의 구체적 중수 연대를 확정하는 문장은 아직 넣지 않았다.

## 공개 전 남은 작업

1. 공식 원문을 실제로 읽고 12장면/문제/카드의 주장과 정확한 출처를 대조한다.
2. 실제 운영 Firebase 전체 보안 규칙을 점검하고, 병합 규칙의 에뮬레이터 검사를 통과시킨다. 새 경로의 계정 저장·재로그인·다른 기기 복원을 검증한다.
3. iPhone/iPad Safari·Android Chrome 실기기에서 뒤로가기·입력·스크롤·음성·기존 GPS 연결을 확인한다.
4. 역사 검증 후 `published`와 출처 검증 상태를 함께 갱신하여 정식 배포한다.
